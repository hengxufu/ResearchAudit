# 3.0 phased implementation and verified scope

The 2.0 baseline was preserved. New features are additive and use the existing nine pages, explicit process runner and evidence storage.

| Phase | Implementation | Acceptance |
|---|---|---|
| 0 Audit | Check clean baseline, routes, tests, dependencies, collector, execution and asset storage | 55 baseline tests and build passed |
| 1 Reproduction | Entry-code/runner evidence, versioned manifest, explicit replay, tolerance and distribution reports, five-dimension scorecard | Real two-layer NumPy training, source-change refusal, pre-enqueue fault recovery, duplicate prevention |
| 2 Workflow | Versioned DAG, reference resolution, retry/conditions, shared command limits, owned cancellation, conservative restart | Command → statistics → audit → SVG → PDF; retries, cycles, branches, parallel IDs, bad-reference termination |
| 3 Data Studio | Contained assets, metadata/header inspection, HDF5/NPY slicing, bounded NPZ/table/image reads | Real sparse large-shape HDF5 and dense 32 MB benchmark; object/traversal/external-link refusals |
| 4 Professional analysis | Training history/diagnosis, SO(3) pose errors/failure rows, driven-energy balance, source-column convergence/sensitivity | q/−q, 90° rotation, 3-4-5 translation; Python and compiled C++ energy output; empirical order 2 |
| 5 Knowledge/interoperability | Revisioned support/conflict claims and graph; Notebook v4 stored evidence | Stale-update refusal, missing-ref refusal, graph edge and notebook no-execution tests |
| 6 Integrated UI and verification | New tools in existing pages, actual API connections, browser regressions and performance measurement | See v3_acceptance.md and v3_benchmark_result.json |

Subsequent priorities, not claimed complete:

1. Target-process self-report/lockfiles, CUDA/PyTorch/toolchain capture, controlled environment reconstruction and actual PyTorch CPU/GPU replay acceptance. Current runner versions and entry snapshots do not certify a full target environment.
2. Immutable code/input materialization into a rerun workspace with full dependency closure. Current replay refuses declared source changes but uses the current cwd and external asset references.
3. Long-running production endurance, hard OS resource quotas/process ownership across crashes, Linux runtime/CI results and remote/HPC execution.
4. Cross-domain protocol-aware queries, model-aligned pose/sample identity joins, semantic dataset checks, failed-image/label synchronized rich inspection, loss/LR causal and GPU bottleneck diagnosis.
5. Workflow runtime parameter matrices, type-aware config forms and drag/edge editing, user-defined plug-in node registration, checkpoint continuation rather than conservative Interrupted status.
6. Full MLflow/DVC/RO-Crate round-trip conformance; current mature format/reference adapters are retained, not presented as full platform equivalence. Schema-validated full Notebook conformance and rich output/image adoption are deferred.
7. More array formats, distributed/chunk-parallel analyses, dataset-level quality pipelines and multi-GB import formats without whole-series JSON materialization.
8. Fully localized forms, richer report editing, project-scoped indexed knowledge search and graph exploration beyond the bounded overview.

Every extension should preserve the separation among record integrity, reproducibility and scientific correctness. It should add tests around source identity/units/evaluation contracts before introducing higher-level automation.
